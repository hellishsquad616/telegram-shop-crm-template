# Telegram Shop CRM — публичный шаблон

Обезличенный каркас Telegram-бота для интернет-магазина. Это самостоятельная копия исходников с новой историей Git. Здесь нет рабочей базы, заказов, клиентов, сотрудников, токенов, cookies, серверных настроек и финансовых отчётов исходного магазина.

## Возможности

- Оплаченные заказы Tilda через защищённый webhook, импорт CSV, поиск и просмотр заказов.
- Продажи и выручка за день, период, категории и отдельные модели товаров.
- Создание, удаление и синхронизация промокодов Tilda; использования, покупатели, суммы и купленные модели по промокоду.
- Права сотрудников на заказы, статистику, промокоды и настройки.
- Проверка заказов МойСклад, ответы в темах поддержки, подарочные шарфы с резервированием и подтверждением второго подарка.
- Возвраты ЮKassa и Яндекс Пэй: проверка оплаты, выбор позиций, подтверждение владельцем, журнал операций, восстановление проверки и защита от повторного возврата.

Названия DEMO PUFFER, DEMOZIP и DEMO SCARF в коде и тестах — демонстрационные. Свои категории и правила сопоставления можно задать в настройках или в `sales_categories.py`. Интеграции потребуют настройки под ваш магазин.

## Быстрый запуск

Нужны Python 3.9+ и собственный Telegram-бот.

```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
```

Заполните локальный `.env`: `BOT_TOKEN` и `ADMIN_IDS`. Для Tilda также укажите собственные `TILDA_PROMOCODES_PROJECT_ID`, `TILDA_EMAIL` и `TILDA_PASSWORD`.

```bash
python bot.py
```

Первая база создаётся пустой. Сотрудников и права добавляет администратор через меню. Не используйте реальные ключи и рабочую базу для тестов.

## Заказы и промокоды Tilda

Задайте случайный `TILDA_WEBHOOK_SECRET` и HTTPS-адрес в `PUBLIC_BASE_URL`. Запустите приёмник:

```bash
uvicorn webhook:app --host 127.0.0.1 --port 8000
```

В Tilda укажите адрес `https://crm.example.com/webhooks/tilda/ВАШ_СЕКРЕТ`, заменив домен и секрет своими. `/health` возвращает состояние приложения. Бот и webhook должны использовать один `CRM_DB_PATH`.

Автоматизация промокодов использует Playwright и авторизованную сессию Tilda:

```bash
python -m playwright install chromium
python tilda_login.py
```

Сессия сохраняется локально в `.auth/`. После настройки промокоды создаются в Telegram. Для статистики нужны полученные от Tilda заказы с данными об оплате, скидке и составе покупки. В новом экземпляре исторических продаж нет.

## МойСклад, темы поддержки и возвраты

Скопируйте `config/refunds_config.example.json` в `.secrets/refunds_config.json`. Укажите собственные Telegram ID владельца, группы и темы, магазин платежей, организацию и пример документа МойСклад. Для общей организации обязательно задайте `ms_brand_scope`, ограничивающий операции вашим проектом, каналом продаж или атрибутом.

Секреты вводятся локально через скрытый ввод:

```bash
python refund_setup.py --help
```

`refund_setup.py` содержит отдельные действия проверки ЮKassa, Яндекс Пэй и МойСклад. Сначала проверьте подключения только чтением на своих примерах. Проведение денег по умолчанию выключено; включение выполняется отдельным действием после проверки. Каждый денежный возврат требует подтверждения владельца. Назначение и фискализация должны соответствовать вашему магазину.

Настройки тем хранятся в `app_settings`: `gift_scarves_chat_id`, `gift_scarves_topic_id`, `support_order_info_chat_id`, `support_order_info_topic_id`. Словарь `support_shipment_text` в локальном JSON связывает ваши пометки МойСклад с текстами ответа. Расписание исходного магазина исключено.

Изображения используют данные подтверждённой операции. Подтверждение Яндекс Пэй не является фискальным чеком; статус платёжного сервиса и фискальные реквизиты нельзя подменять.

## Проверки и структура

```bash
python -m unittest discover -s tests
```

Тесты используют временные базы, синтетические заказы и подмены API. Включены тесты оставленных модулей. Разовые скрипты исправления рабочих заказов и связанные с ними тесты исключены.

Основные модули: `bot.py` — меню; `database.py` — SQLite; `promo_statistics.py` — статистика промокодов; `integrations/tilda_promocodes.py` — Tilda; `customer_refunds*.py`, `yandex_refunds.py` — возвраты; `gift_scarves.py` — подарки; `support_order_info.py` — информация об отправке.

`.env`, `.auth/`, `.secrets/`, базы, резервные копии, выгрузки и отчёты исключены через `.gitignore`. Держите их вне Git. Получателю ссылки не нужен доступ к исходному рабочему магазину.
